# Exam Scanner API JSON Documentation

This document describes the structure, possible statuses, and cause codes of the `final_grades.json` output generated by the grading pipeline. This is intended to be used directly by the Flutter front-end to interpret results.

## Root Object
```json
{
    "exam_id": "exam_2026_08_19_001",
    "exam_type": "quiz",
    "num_questions_expected": 28,
    "sheets": {
        "<image_name>": { ... }
    }
}
```

The `sheets` dictionary maps the source image's filename (without the extension) to its specific evaluation results. For instance, if you submit `quiz25.jpeg`, the key will be `"quiz25"`.

## Sheet Object
```json
{
    "global_status": "success",
    "cause": null,
    "ID": "M977",
    "MCQ": {
        "Q1": { "status": "answered", "answer": "A" },
        "Q2": { "status": "blank", "answer": null }
    },
    "needs_review": []
}
```

### `global_status`
The overall status of the sheet. Prioritized top-to-bottom (e.g. if the sheet fails preprocessing, it won't run further to check for mismatches).

1. **`"failed"`**: The image could not be processed. This is a fatal preprocessing error, usually due to missing panels or extreme blur/obstruction.
2. **`"number_mismatch"`**: The geometric structure of the detected bubbles does not match the expected exam configuration (e.g., an extra row or missing column).
3. **`"retake"`**: The number of questions that the model marked as low confidence (requiring manual review) exceeds the `RETAKE_REVIEW_THRESHOLD` (currently > 3).
4. **`"review_needed"`**: Between 1 and 3 questions have low confidence and need manual review from a human.
5. **`"success"`**: The sheet was processed perfectly with zero warnings, zero mismatches, and zero low-confidence bubbles.

### `cause`
Provides specific, localized string keywords describing *why* the sheet received its `global_status`. These are strict keywords designed for Flutter localization/wiring.

- If `global_status` is `"success"` or `"review_needed"`, the `cause` is **`null`**.
- If `global_status` is `"retake"`, the `cause` is `"retake_threshold_exceeded"`.
- If `global_status` is `"failed"`, the `cause` will be one of:
    - `"preprocessing_error"` (Generic failure/fallback)
    - `"panels_missing"` (Neither ID nor MCQ panels were found)
    - `"id_panel_missing"` (Only the ID panel was missing)
    - `"mcq_panel_missing"` (Only the MCQ panel was missing)
- If `global_status` is `"number_mismatch"`, the `cause` can be either a **single string** or an **array of strings** (if multiple structural errors occurred simultaneously). The possible mismatch strings are:
    - `"missing id column(s)"`
    - `"extra id column(s)"`
    - `"missing mcq column(s)"`
    - `"extra mcq column(s)"`
    - `"extra mcq row(s)"`
    - `"extra id row(s)"`

### `MCQ` Object (Per-Question Status)
A dictionary mapping the question key (e.g. `"Q1"`, `"Q2"`) to its result.

```json
"Q1": {
    "status": "answered",
    "answer": "A"
}
```

The `status` of a specific question will be exactly one of the following:

- **`"answered"`**: The student confidently filled exactly one bubble. `answer` is a string (e.g. `"C"`).
- **`"multiple"`**: The student confidently filled more than one bubble. `answer` is an array of strings (e.g. `["A", "C"]`).
- **`"blank"`**: No bubbles were filled for this question. `answer` is `null`.
- **`"review_needed"`**: The model's confidence for the filled bubbles was low (score <= 55%), or there was a mix of confident and low-confidence bubbles. `answer` is an array of the suspected options.
- **`"number_mismatch"`**: A placeholder status assigned to "overflow" questions when the pipeline detects more valid rows than the exam configuration expects. `answer` is `null`.

### `needs_review` Array
An array detailing exactly which questions triggered a `"review_needed"` status. Empty if no review is needed.
```json
"needs_review": [
    {
        "panel": "MCQ",
        "question": "Q7",
        "candidates": ["A", "B"]
    }
]
```

## FFI Integration Notes
The `exam_scanner_ffi` library has been fully synchronized with these changes.
If `stage1_boxes` detects a missing panel (like in the `quiz23` case), the FFI loop will elegantly bypass stages 2-5 and immediately invoke `stage6_scoring` to generate the strict `"failed"` JSON structure output without crashing or hanging.
